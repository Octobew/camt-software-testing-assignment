# Lab 00 — บันทึกผล

## ขั้นที่ 2: รัน test ครบทุก boundary

รันบน macOS (arm64), Node v24.11.1, Docker Compose v2.40.3

| | unit | integration | e2e |
|---|---|---|---|
| ผลรัน | 6/6 ผ่าน | 1/1 ผ่าน | 1/1 ผ่าน |
| เวลาที่ใช้ (โดยประมาณ) | ~1.6 วินาที (Jest 0.86 วินาที) | ~9 วินาที (Jest 1.3 วินาที ที่เหลือเป็นเวลาเปิด DB + Liquibase) | ~16 วินาที (ตัว test 0.5 วินาที ที่เหลือเป็นเวลา build และเปิด container) |
| ต้องมี Docker ไหม | ไม่ต้อง | ต้อง ใช้ Postgres (port 5433) + Liquibase | ต้อง ใช้ app container + Postgres e2e + Liquibase |
| ถ้า test พัง บอกได้แม่นแค่ไหนว่าพังที่ไหน | แม่นมาก ชี้ได้ถึง function และบรรทัด assert ว่าคาดหวังค่าอะไรแต่ได้ค่าอะไร | ปานกลาง รู้ว่า flow สมัครสมาชิกพัง แต่ต้นเหตุอาจอยู่ที่ route, service, repository, SQL หรือ schema | น้อยที่สุด รู้แค่ว่าเส้นทางของผู้ใช้ทั้งเส้นพัง (เช่น HTTP status ผิด) ต้นเหตุอาจเป็นโค้ด, DB, container หรือ network |

**สิ่งที่สังเกตได้:** ยิ่ง test ครอบคลุมระบบกว้างขึ้น ก็ยิ่งช้าลง ต้องพึ่งเครื่องมือมากขึ้น และหาจุดที่พังได้ยากขึ้น
แต่ก็ได้ความมั่นใจว่าทุกส่วนของระบบทำงานด้วยกันได้จริง (แนวคิด test pyramid)

> หมายเหตุ: e2e รอบนี้เร็วเพราะ Docker มี image cache อยู่แล้ว ถ้าเป็นรอบแรก build จะใช้เวลาประมาณ 3–5 นาที
